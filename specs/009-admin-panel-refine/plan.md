# Implementation Plan: Admin Panel (Refine.dev)

**Branch**: `009-admin-panel-refine` | **Date**: 2026-03-30 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/009-admin-panel-refine/spec.md`

---

## Summary

Build a standalone React + TypeScript admin panel in `admin/` at the repository root
using Refine.dev (`@refinedev/antd`, `@refinedev/react-router`, `@refinedev/simple-rest`)
backed by the existing NestJS REST API. The panel manages four entities — Orders,
Couriers, Users (staff accounts), and Route History — using a sidebar-nav, drawer-based
CRUD pattern per Constitution Principle VIII. A small set of new NestJS CRUD endpoints
(Couriers list/detail/edit, Users CRUD, Route History list) must be added to the
backend alongside the frontend implementation.

---

## Technical Context

**Language/Version**: TypeScript 5.x (React 18 frontend) + Node.js 20 LTS (NestJS backend additions)
**Primary Dependencies**:
- Frontend: `@refinedev/core`, `@refinedev/antd`, `@refinedev/react-router`,
  `@refinedev/simple-rest`, `antd@^5`, `react-router@^6`, `@tanstack/react-query@^5`,
  `axios`, `vite`
- Backend additions: existing NestJS 10 / TypeORM 0.3 stack (no new packages)

**Storage**: N/A (frontend reads from NestJS REST API; backend additions use existing PostgreSQL)
**Testing**: Vitest (frontend unit), existing NestJS Jest (backend additions)
**Target Platform**: Modern desktop browsers (Chrome, Firefox, Safari, Edge) + tablet; mobile ≥ 768px as bottom-sheet mode
**Project Type**: Standalone SPA (admin/) + minor NestJS controller additions
**Performance Goals**: Initial data load ≤ 3s on broadband (SC-004); order workflow under 60s (SC-003)
**Constraints**: Zero full-page navigations during CRUD (SC-002); Drawers ≤ 720px, Modals ≤ 480px (Constitution VIII)
**Scale/Scope**: 4 entity sections; ~20 components; ~8 React Query hooks; 8 new backend endpoints

## Implementation Phases

### Phase 1 — Backend: Missing CRUD Endpoints

Add the NestJS endpoints the admin panel requires but don't yet exist.

**1.1 Couriers Management Endpoints**
- Extend `CouriersModule` with a new `CouriersController` (separate from `CourierTrackingController`)
- Add `GET /api/v1/couriers` — paginated list, search by name/phone, scoped to `owner_id`
- Add `GET /api/v1/couriers/:id` — detail with latest CourierPosition + current CourierShift
- Add `PATCH /api/v1/couriers/:id` — update first_name, last_name, phone, status, login, telegram_chat_id
- Guards: `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles(OWNER, MANAGER, ORDER_OPERATOR)`
- Swagger: `@ApiTags('couriers-admin')`, `@ApiBearerAuth()`, response decorators

**1.2 Users (Staff) Management Endpoints**
- Create new `UsersModule` at `src/users/`
- Add `GET /api/v1/users` — list staff in tenant (owner/manager/order_operator roles)
- Add `POST /api/v1/users` — create staff; role restricted to manager/order_operator for non-owners
- Add `PATCH /api/v1/users/:id` — update name, role
- Add `DELETE /api/v1/users/:id` — delete (owner-only)
- Guards: all endpoints require JwtAuthGuard + RolesGuard; DELETE/POST restricted to OWNER
- **Implementation note**: "Users" maps to the owners/staff table. Exact table depends on
  whether staff accounts are separate from the Owner entity. If Owner IS the user, use
  the existing `owners` table scoped to `owner_id` for sub-accounts.

**1.3 Route History List Endpoint**
- Add `GET /api/v1/route-history` to `CourierTrackingController` (or new controller)
- Queries `courier_location_history` grouped by order; supports filters: courier_id, order_id, from/to date
- Returns paginated list with derived fields: courier_name, order_number, total_distance_meters, point_count
- Guards: OWNER, MANAGER, ORDER_OPERATOR

### Phase 2 — Frontend: Admin SPA Scaffold

Set up the `admin/` project with all infrastructure before building entity pages.

**2.1 Project Setup**
```bash
npm create vite@latest admin -- --template react-ts
cd admin
npm install @refinedev/core @refinedev/antd @refinedev/react-router @refinedev/simple-rest
npm install antd @ant-design/icons react-router axios @tanstack/react-query
```

**2.2 Auth Provider** (`admin/src/authProvider.ts`)
- `login()`: POST to login endpoint, store `access_token` in localStorage
- `logout()`: clear localStorage, redirect to `/login`
- `check()`: verify token exists (and optionally check expiry)
- `getIdentity()`: decode JWT payload, return `{ id, name, role, owner_id }`
- `onError()`: on 401, call logout()

**2.3 Data Provider** (`admin/src/dataProvider.ts`)
- Base: `@refinedev/simple-rest` pointed at `VITE_API_URL`
- Axios instance with `Authorization: Bearer <token>` interceptor
- Map `{ data, meta }` response shape to Refine's expected `{ data, total }`

**2.4 App Root** (`admin/src/App.tsx`)
```tsx
<Refine
  authProvider={authProvider}
  dataProvider={dataProvider}
  routerProvider={routerBindings}
  resources={[
    { name: 'orders',        list: '/orders',         show: '/orders/:id' },
    { name: 'couriers',      list: '/couriers',        edit: '/couriers/:id/edit' },
    { name: 'users',         list: '/users',           create: '/users/create', edit: '/users/:id/edit' },
    { name: 'route-history', list: '/route-history',   show: '/route-history/:id' },
  ]}
>
```

**2.5 Layout** (`admin/src/components/AppLayout.tsx`)
- `ThemedLayoutV2` with custom `Sider` showing the 4 navigation items
- Breadcrumb disabled (flat 1-level nav)

### Phase 3 — Frontend: Orders Section (P1)

**3.1 OrdersPage** (`admin/src/pages/orders/OrdersPage.tsx`)
- `useTable` hook from `@refinedev/antd` for paginated, server-side table
- Columns: Order #, Status (tag), Client Phone, Courier Name, Pickup Address, Created At
- Inline filter: Status dropdown above table (uses `setFilters()`)
- Skeleton: `Table` with `loading={isLoading}` uses Ant Design skeleton automatically
- Row click: sets `selectedOrderId` → opens `<OrderDrawer>`

**3.2 OrderDrawer** (`admin/src/pages/orders/OrderDrawer.tsx`)
- Width: 720px; `placement={isMobile ? 'bottom' : 'right'}`
- Uses `useShow()` to fetch `GET /orders/:id`
- Sections: Order Info, Items list, Courier info, Lifecycle timestamps, Audit log
- "Cancel Order" button → opens `<CancelOrderModal>` (if status is not terminal)

**3.3 CancelOrderModal** (`admin/src/pages/orders/CancelOrderModal.tsx`)
- Width: 480px
- Optional reason textarea
- On confirm: `useCustomMutation` → `POST /orders/:id/cancel`
- On success: `invalidateQueries(['orders'])`, close modal + drawer, show toast

### Phase 4 — Frontend: Couriers Section (P1)

**4.1 CouriersPage** (`admin/src/pages/couriers/CouriersPage.tsx`)
- `useTable` with `syncWithLocation` for search: search input calls `setFilters([{ field: 'search', ... }])`
- Columns: Name, Phone, Status (tag), Login, Created At
- Row action icons (edit, delete) visible on hover via CSS `opacity` toggle
- Row click → opens `<CourierDrawer>` in view mode

**4.2 CourierDrawer** (`admin/src/pages/couriers/CourierDrawer.tsx`)
- Width: 720px
- View mode: shows full profile including current_position (lat/lng text), shift status
- Edit mode: `useDrawerForm` toggles form fields; Save pinned at bottom
- Unsaved changes: `form.isFieldsTouched()` → `Modal.confirm` before close
- Status change (available ↔ unavailable): inline select in edit mode

### Phase 7 — Polish & Cross-Cutting Concerns

**7.1 Mobile bottom-sheet**
- `useBreakpoint` hook from `antd/lib/grid`
- All Drawers receive `placement={screens.xs ? 'bottom' : 'right'}`

**7.2 Empty states**
- `Empty` component from Ant Design with descriptive message and primary action button
- Wired into each Page component when `data.length === 0 && !isLoading`

**7.3 Error handling**
- Axios response interceptor: 401 → authProvider.logout()
- Refine `notificationProvider` (from `@refinedev/antd`) handles success/error toasts automatically
- Manual error toasts for custom mutations (cancel, status change)

**7.4 Login page**
- Refine `<AuthPage type="login">` with Ant Design styling
- Connects to `authProvider.login()`

**7.5 Environment configuration**
- `admin/.env.example`: `VITE_API_URL=http://localhost:3000`
- `admin/.env.local` (gitignored)
